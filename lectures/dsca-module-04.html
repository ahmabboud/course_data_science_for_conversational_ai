Part one of two · about 25 minutes

Where do facts live?

First the vocabulary and the two obvious ideas that do not work. Then the first real answer.

Start with the vocabulary

Session memory ends. Persistent memory does not.

Definition

Session memory: the message list of one running conversation. It ends when the program ends. Persistent memory (also called cross-session or long-term memory): facts saved outside the program, so a later session can read them. user_id: a name for one person that stays the same across all their sessions.

The obvious idea, and its limits

Sending the whole history costs far more tokens and time

Definition

Mem0 and Zep: two memory tools we study today. Token: a small piece of text. p95: 95 of every 100 replies were faster than this time (the slow end users notice). Score: the share of test questions answered correctly, judged by another LLM. Sending the whole chat every time is slow and costly. In the Zep test the memory even scored higher; in the Mem0 test it scored a little lower.

A recap from Module 3, now used for memory

Memory is found by meaning, not by exact words

Definition

Embedding: a list of numbers for the meaning of a text (Module 3). Similarity score: how close two meanings are; higher is closer. A memory is found even when the words differ: "live" matches "lives".

The first answer: Mem0

Pull out the facts, then keep one clean list

OperationWhenExample
ADDA new fact, nothing similar storedFirst mention of where the user lives
UPDATEA stored fact must be corrected"Beirut" becomes "Paris"
DELETEA stored fact is now falseThe user sold the car
NOOP (no operation)Nothing to change: do nothingThe user repeats "I live in Paris"
The design on one example

UPDATE replaces. The old fact is gone.

Read this critically

The design says UPDATE. The library says ADD.

The difference

add() skipped a repeated fact, but did not replace a changed one: both ADDs stored a fact. Your code must call update() and delete() (shown in the demo).

The second answer needs a new picture

A graph stores a fact as an arrow between two things

Definition

Knowledge graph: facts stored as boxes joined by labelled arrows. Entity: a box, a thing such as a person, a place or an order. Fact (or edge): one arrow with its two ends, for example (user, lives_in, Paris). The labels lives_in and works_for are the relations. The user is drawn twice only to keep the arrows straight. The example facts are invented for teaching.

The second answer: Zep and Graphiti

A fact is closed, never deleted

Definition

Valid from and ended (the paper calls them t_valid and t_invalid): the time range in which a fact was true. Zep also records when the system learned the fact (t_created, t_expired), so it tracks two timelines. The dates here are invented for teaching.

How Zep builds its memory

Zep extracts facts from messages, then groups them

Definition

Extract: an LLM reads text and writes down entities and facts. Entity: a thing, such as a person or a place. Fact: a link between two entities. Group (community detection): put entities that are linked to each other a lot into one set, with a summary.

Two designs, two jobs

Mem0 and Zep side by side

Mem0 (extract and update)Zep (temporal graph)
What is storedShort facts in a flat listEntities and facts, each with dates
Where a fact goes when it changesReplaced (UPDATE)Closed with an end date, kept
Can it answer "as of when?"Not built inYes

Part two of two · about 40 minutes

Time, size and privacy

Facts that change over time, a conversation that must stay short, and the cost of remembering a person.

A different problem: length, not forgetting

Three ways to shorten a conversation

OptionWhat it doesWhat can go wrong
TruncateDrop the oldest turns when a limit is reachedCheapest. It silently drops the one fact a later question needs.
SummariseReplace old turns with a short summaryKeeps more, but a summary loses details.
Segment, then compressCut the chat into topics, remove filler words from each, then search them (SeCom)An extra model call for every segment.
Definition

Compaction: making an old conversation smaller so it still fits the model's context window. Truncate: cut off. Summarise: write a shorter version. This is separate from persistent memory: memory is for facts across sessions, compaction is for length inside one.

The demo runs the “Summarise” option from the last slide

Over the limit? Replace the oldest messages with one summary

Why 6 and not 5

The limit is 20 messages and the chat has 25. The summary is a message too, so it needs a place. Keep the 19 newest, fold the other 6 into 1 summary: 1 + 19 = 20. Nothing is silently dropped.

Real numbers from the demo. Its summariser is a placeholder, so the logic can be tested without an API call. A real system would ask the model to write the summary.

Assigned reading · better than one turn or the whole session

Cut the chat by topic, then search the piece that matches

What are these topics?

The paper's own example chat, which jumps between unrelated subjects. A, prosecutor's fallacy: mixing up “rare for the innocent” with “probably guilty”. B, base rate fallacy: ignoring how common something is. C, World War II. You do not need to know them: the lesson is how the chat is cut.

SeCom (Pan et al., ICLR 2025). Assigned reading. The authors' Figure 1 (CC BY 4.0).

The bill that comes with remembering

A memory bank is a record about a person

Data you keep

Every stored fact is data about one person.

A leak that looks like confusion

With the wrong id, one person sees the facts of another person.

Errors that stay

A wrong or old fact does not fix itself.

Delete on request

You need a way to delete, and to prove it worked.

Why a memory layer at all

Without memory, the agent contradicts what it was told

Reason 1

A relationship lasts weeks or months. The history outgrows even a very large context window.

Reason 2

Real talk wanders. A key fact can be buried under hours of unrelated words.

Why not just count matching words?

Truth: "Alice was born in March." Answer: "Alice is born in July." The words overlap, so word-overlap scores (F1, BLEU) stay high, though the fact is wrong. So the authors add an LLM-as-a-Judge score.

The one-sentence version

Every memory here is RAG over a store that an LLM writes and maintains. Plain RAG stores raw chunks; memory stores cleaned facts. Embedding model: turns text into numbers so similar meanings can be found (Module 3). Your project needs one embedding model and one LLM.

Demo step 2

The library adds. Our code keeps one current fact.

r1 = memory.add(first_turn,  user_id=USER_ID)
# "Hi, I'm based in Beirut."
r2 = memory.add(second_turn, user_id=USER_ID)
# "I just moved from Beirut to Paris for work."

memory.update(r1["results"][0]["id"],
    text="User currently lives in Paris for work.")
memory.delete(r2["results"][0]["id"])
What to notice
  • add() takes the turn and a user_id
  • It returns what it did, with an id for each memory
  • Our code then does the conflict step: update one, delete the other
Why the extra code

This is the gap from Part 1: the library stored both facts. The application is responsible for keeping one current fact.

Demo step 4

Fold the oldest turns, keep the rest

def compact(messages, max_live_turns, summarize):
    if len(messages) <= max_live_turns:
        return messages
    overflow = len(messages) - max_live_turns + 1
    old, kept = messages[:overflow], messages[overflow:]
    text = summarize(old)
    note = "Earlier conversation, summarised: " + text
    return [{"role": "system", "content": note}] + kept
What the run printed
  • input turns: 25
  • output messages: 20
  • first message: system, "Earlier conversation, summarised: covered 6 earlier turns..."
A stand-in

The summariser here is a stub, so the splice can be tested without a model call. A real system sends the old turns to the same model as the rest of the agent.

Demo step 5

Delete, then prove it

memory.delete_all(user_id=user_id)

hits = memory.search("anything about this user",
                     filters={"user_id": user_id})
stored = memory.get_all(filters={"user_id": user_id})

confirmed = (len(hits["results"]) == 0
             and len(stored["results"]) == 0)
What the run printed
  • search hits after delete: 0
  • stored memories after delete: 0
  • confirmed deleted: true
Verified, not assumed

The code does not trust that the delete call ran without an error. It checks, twice, that nothing is left.

Worth knowing before you copy the code

user_id is passed in two different ways

CallsWhere the user id goes
add() and delete_all()A plain argument: user_id="..."
search() and get_all()Inside a filter: filters={"user_id": "..."}
mem0ai 2.0.20. Passing it the wrong way raises a ValueError.
Decide out loud

The store holds "lives in Paris". The user says, "I moved to Lyon." You call add(). What does the store hold afterwards, with the mem0ai version this course pins?

So you recognise them instead of debugging blind

Four problems you will meet

SymptomUsual cause
Recall works only inside one runMemory is keyed by a session id, or the store is held in the program and never saved to disk
The same fact appears twice, or two facts disagreeadd() was called without checking the result, so a changed fact was added next to the old one
One user sees another user's factsuser_id is fixed in the code, or comes from something shared, such as a test string
A long chat eventually fails on lengthThe compaction step was written but is not called in the main loop
Fastest way to tell which one you have

Print the user_id and the full result of every memory call. If a second run cannot see the first run's facts, it is the first bug. If the same claim appears twice, it is the second. If two different users return the same facts, it is the third.

Discussion

Three ways a memory goes wrong

Stale fact

Out of date

A fact was true, then changed, and the agent never learned. It states the old value with confidence.

Wrong recall

Wrong person

A fact is attached to the wrong user or the wrong thing. The agent tells someone something true about somebody else.

Forget me

On request

A user asks the agent to forget. Is everything gone, including the summaries?
